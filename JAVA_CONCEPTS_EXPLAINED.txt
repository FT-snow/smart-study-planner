================================================================================
SMART STUDY PLANNER - JAVA CONCEPTS USED IN THE BACKEND, EXPLAINED SIMPLY
================================================================================

This file explains every Java (OOP) concept the Spring Boot backend uses, in
plain words. Only concepts covered in the CSC2104 lectures (and ordinary
course-level Spring annotations) appear here. For each concept:

  WHAT it means    -> one short sentence
  WHERE to see it  -> the exact file (all under backend/src/main/java/)
  WHY it is there  -> what it buys us in this project

The lecture numbers refer to the lessons that live in
public/java/studyplanner/lessons/ - every idea in the backend has a direct
relative among the demos you compiled during lectures.


--------------------------------------------------------------------------------
1. CLASSES AND OBJECTS  (Lectures 01-02, 10, 13)
--------------------------------------------------------------------------------
WHAT: A class is a blueprint; an object is a real thing built from it, with
      its own data.

WHERE:  domain/Subject.java  domain/Task.java  domain/StudySession.java

WHY: Subject is the form "course": every course the student adds on the page
     becomes one object built with new Subject("CSC2104", "Java OOP", 240,
     "blue"). Tasks and sessions work the same way.


--------------------------------------------------------------------------------
2. CONSTRUCTORS  (Lecture 02)
--------------------------------------------------------------------------------
WHAT: A special method that runs when an object is created, to set it up.

WHERE: Subject(String code, String name, int targetMinutes, String color)

WHY: Inside the constructor the setters run, so a freshly built object is
     already checked and valid ("constructors and object setup").


--------------------------------------------------------------------------------
3. ENCAPSULATION - private fields, getters, setters  (Lecture 18)
--------------------------------------------------------------------------------
WHAT: Hide the data (private), and let outside code read or change it only
      through methods that check the values first.

WHERE: every domain class, e.g. Subject.setTargetMinutes():

    public void setTargetMinutes(int targetMinutes) {
        if (targetMinutes < 15 || targetMinutes > 2400) {
            throw new IllegalArgumentException("Weekly target must be...");
        }
        this.targetMinutes = targetMinutes;
    }

WHY: No page, no user, no other class can sneak in a negative target or an
     empty name. The object protects itself - bad data never gets saved.


--------------------------------------------------------------------------------
4. if / else, LOOPS AND SIMPLE TYPES  (Lectures 03-06)
--------------------------------------------------------------------------------
WHAT: Conditions, for-each loops, ints, Strings, booleans - the everyday
      building blocks.

WHERE: service logic lives directly in the controllers, e.g.
       api/TaskController.all() splits tasks into two lists and sorts each
       one; logic/ProgressCalculator.compute() counts with plain counters.

WHY: The dashboard does not stream or map anything; it is Lecture 06 applied
     directly: "for each task in the list: if completed, count it".


--------------------------------------------------------------------------------
5. ArrayList AND HashMap  (Lecture 09 + practice sessions)
--------------------------------------------------------------------------------
WHAT: Objects that hold many other things. ArrayList grows as needed;
      HashMap stores pairs of (key, value) like a dictionary.

WHERE: TaskController.all() builds "open" and "done" ArrayLists;
       ProgressCalculator.compute() uses a HashMap<Long, Integer> to add up
       finished minutes per subject.

WHY: Plain collections are all that is needed to sort the to-do list and
     compute the weekly progress bars.


--------------------------------------------------------------------------------
6. THE final KEYWORD AND STATIC FIELDS  (Lecture 19)
--------------------------------------------------------------------------------
WHAT: static belongs to the class itself, not one object; final never
      changes after it is set.

WHERE: domain/PlannerSettings.java

    public static final long SINGLETON_ID = 1L;

WHY: There is exactly one settings row and its id is always 1. ProgressCalculator
     also declares DEFAULT_WEEKLY_GOAL_MINUTES the same way.


--------------------------------------------------------------------------------
7. INTERFACES  (Lectures 29-30)
--------------------------------------------------------------------------------
WHAT: An interface is a promise-list: method names a class agrees to provide.

WHERE: domain/Completable.java

    public interface Completable {
        boolean isCompleted();
    }
    // then: public class Task implements Completable { ... }
    //       public class StudySession implements Completable { ... }

WHY: Tasks and sessions are different, but both can be finished. Saying so
     through an interface is exactly the Lecture 30 Trackable idea.


--------------------------------------------------------------------------------
8. INHERITANCE IN JAVA - toString() OVERRIDING  (Lectures 22, 27)
--------------------------------------------------------------------------------
WHAT: Every class automatically inherits from the Object class; a child may
      replace (override) a method such as toString().

WHERE: every domain class ends with its own:

    @Override
    public String toString() { ... }

WHY: Printing any subject, task or session now describes it nicely. This is
     the small, taught version of overriding - one replaced method.


--------------------------------------------------------------------------------
9. ANONYMOUS CLASSES FOR SORTING  (Lecture 21)
--------------------------------------------------------------------------------
WHAT: A class written at the spot where it is used, with no name.

WHERE: TaskController.all() and StudySessionController.all():

    open.sort(new Comparator<Task>() {
        public int compare(Task a, Task b) { ... }
    });

WHY: To sort you must supply "how to compare two tasks". The anonymous
     Comparator is the one-off trick from Lecture 21 used for real work.


--------------------------------------------------------------------------------
10. EXCEPTIONS - BUILT-IN CLASSES + ONE CENTRAL CATCH  (Lectures 36-37)
--------------------------------------------------------------------------------
WHAT: When something is wrong, throw one of Java's own exception classes;
      elsewhere, catch it and continue politely.

WHERE: setters throw new IllegalArgumentException("...") when a value is not
       acceptable; controllers throw new NoSuchElementException("...")
       when an item is missing; api/ApiExceptionHandler catches all of them
       in one place and turns them into friendly JSON messages.

WHY: No new classes were invented - the planner reuses Java's built-in
     exceptions with clear messages. The central @ExceptionHandler file is
     the web version of try/catch/finally: one catch, clean answers
     (400 wrong input, 404 missing item, 500 unexpected).


--------------------------------------------------------------------------------
11. DATES - LocalDate AND LocalTime  (data types from Lecture 03, advanced form)
--------------------------------------------------------------------------------
WHAT: Java types for a calendar date ("2026-10-21") and a clock time
      ("16:30"). Think of them as strings with superpowers: they can be
      compared and have .plusDays(1).

WHERE: Task.dueDate, StudySession.date/.time, and currentWeekStart() in
       ProgressCalculator (Monday of this week = today minus weekday - 1).

WHY: Because they are real dates, "is the task overdue?" is just
     dueDate.isBefore(today) instead of string gymnastics.


--------------------------------------------------------------------------------
12. HOW A TASK KNOWS ITS SUBJECT (linking rows by id)
--------------------------------------------------------------------------------
WHAT: Instead of nesting objects, a task stores one number: the subject's id.

WHERE: domain/Task.java and domain/StudySession.java keep a plain
       Long subjectId field.

WHY: Simple and matchable: when the page asks for subject 1, the backend
     looks up subject 1; removing a subject simply removes all rows whose
     subjectId equals its id (see SubjectController.remove).


--------------------------------------------------------------------------------
13. SPRING BOOT - THE GLUE  (beyond the lectures, kept as annotations)
--------------------------------------------------------------------------------
WHAT: Spring Boot is a Java framework that turns ordinary classes into a
      working web app. You only learn a few fixed annotations:

      @SpringBootApplication  - the start button (StudyPlannerApplication)
      @RestController         - "this class answers web requests"
      @GetMapping / @PostMapping / @PatchMapping / @DeleteMapping + a URL
      @PathVariable, @RequestBody - to receive an id or a JSON body
      @ResponseStatus(...)    - which status code to answer with
      @Transactional          - "do this as one all-or-nothing step"

WHERE: api/*Controller.java hold the business rules directly; repo/*.java
       are empty interfaces whose method bodies Spring writes for us
       (findAll, save, findById); bootstrap/SamplePlanBootstrap.java creates
       the sample plan on first launch and on the reset button.

WHY: The Java you learned (classes, loops, if) still writes every rule.
     Spring just gives those rules a web address.
